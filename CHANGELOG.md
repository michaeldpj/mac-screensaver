# Changelog

All notable changes to this project documented here.

Older dated entries below preserve historical implementation and art-generation decisions. Where they
conflict with the latest release section or current runbooks, they are superseded history—not current guidance.

## [1.0.0] - 2026-10-04

### Added
- Signed and notarized DMG download for the Seasons menu-bar app, built by `scripts/build-dmg.sh`
  and published on GitHub Releases. The app now carries version 1.0.0 (build 1).
- The Seasons menu-bar app now has a persisted **External Displays — Ultra-Lite 30 FPS
  (Experimental)** option. It selects the same bounded 2880/30 FPS path as the proven
  `SEASONS_EXT_ULTRALITE` test launch and survives normal launch and Launch at Login. Authorization is
  passed only by the app; the legacy saver and preview remain fail-closed by default.
- Hero species: a season can declare `heroSpecies{}` — its own sprite set, sizes, aero, and material for the hero crossings, carved into a dedicated particle range so heroes wear different art than the ambient fall. Spring's heroes are now whole cherry blossoms (3 sprites); winter's are oversized ornate crystals (2 sprites, slow majestic spin). Hero events are thereby available to any season that brings hero art, not just leaf/petal models.
- Two non-seasonal styles, config-only: **Embers** (rising warm motes that flicker and drift in light gusts — riser physics added: strictly-upward populations spawn below the viewport and recycle off the top) and **Stars** (a slowly drifting cool-white field that twinkles). Both in the menu-bar picker.
- Fixed named styles (Rain, Embers, Stars) silently falling back to Auto when picked from the menu: the persisted selection now round-trips as a raw style name (`Prefs.selectionName`), and the view resolves any unrecognized non-off name via the catalog regardless of whether it came from the env override or the picker.

### Changed
- The menu item is now **External Displays — Ultra-Lite 30 FPS**, without "(Experimental)", since
  the mode runs three externals as one panorama without the earlier DCP panics.
- README audited against the code: install section, current layout and targets, the full style list,
  and the `streak` glyph type.
- External Ultra-Lite HQ now uses a 2880×1620 maximum source drawable at forced scale 1.0, 30 FPS,
  15% particles, sRGB BGRA8 with EDR off, and no bloom or DoF. Three maximum-size externals target
  30/30/30 at about 419.9M source pixels/s (2.25× the former 1920×1080 envelope). The no-effects
  composite samples scene directly, leaving only scene+CoC retained (~71.2 MiB/display, ~213.6 MiB for
  three). External DCP safety remains unproven; built-in-only is still the default and all external
  trials remain staged, human-supervised experiments.
- Sprite quality now uses strict atomic 1024px set publication and all-JSON validation. The runtime loader
  rejects an entire incomplete or malformed declared set, builds alpha-weighted linear-light RGB /
  RMS-alpha mips, derives maps at every mip, and samples with 16× anisotropy. Current sprite runbooks now
  specify high-detail photoreal source art and bright natural color; older fal.ai/Ideogram and muted-color
  entries below are retained only as project history. There is no 2048px runtime path.
- Ship cleanup pass (dual-reviewed): wind field cost cut ~60% (xy-only curl — 16 noise evals instead of 36 — and the in-gust turbulence boost hoisted out of the lane loop, paid at most once and never in calm air); parked-reserve and firefly wind checks use a flop-cheap gust-only sampler; snow micro-dance uses two plain noise reads instead of a full curl; the common native-res path composites straight to the drawable again (the full-res `present` copy now runs only after MetalFX, with a graded-frame fallback when scaler creation fails — never an unwritten drawable); the panic-avoidance display policy now lives ONCE in `Sources/DisplayPolicy.swift` (shared by preview + app, EDR pinned to the built-in panel since both DCP panics fired from externals); double-flash firefly identity keyed off spawn-stable bits (was re-rolling per frame off the advancing seed — rendered as flicker); species-level `aero{}` now actually applies, merged field-by-field species → season → model defaults; hero events clamp to leaf/petal models; dead SimParams/Particle fields removed (`wind`, `swayAmp`, `swayPeriodMin/Max`, `freq`); shared `ShaderCommon.h` (vhash/luma) and `WindModel.epochEvent` dedupe the hash/scheduler cores; draw units now built FROM the sim's species ranges so alignment is structural.

### Fixed
- Stars no longer leave bright points fixed on OLED pixels. Every star now has guaranteed slow
  diagonal translation, with depth-scaled parallax and panorama-boundary recycling, while retaining
  the existing twinkle. A source-of-truth configuration test prevents zero-motion regressions.
- Fourth SoC panic (2026-06-11, clamshell) closes the last trigger. The SDR default still animated `NSScreen.main`, which in clamshell (externals only) is an external display — and an animated surface on an external panics its coprocessor (`DCPEXT0 - CLLT escalation - power(6)`), the same signature as the June 10 pair. Display selection now pins to the BUILT-IN panel in every mode, extracted to a pure unit-tested `DisplayPlan.decide`; with no built-in present nothing animates and every screen shows the static graded field. `SeasonsView` self-gates the same way so the installed `.saver` — which the ScreenSaver host spawns per display, bypassing the policy — cannot animate an external either. 9 new policy tests including the exact clamshell repro; suite 36/36.
- Season picker selections now actually persist: preferences moved from ScreenSaverDefaults (which only writes inside the legacy screensaver host — from the menu-bar app every value silently vanished, so the picker always reverted to Auto/fireflies) to a plain UserDefaults suite shared by the app, preview, and saver.
- Riser respawns (embers) no longer trip the falling bottom-exit test on their first frame — fresh below-screen spawns were being re-randomized until they landed near the bottom edge instead of drifting in from below (caught by Codex post-push review).
- Third SoC panic (2026-06-10 evening, ladder rung 3) pins the remaining trigger: SDR single-display runs PASSED twice (including through MetalFX), but three simultaneous full pipelines panic the display power rail even in SDR — the failure is aggregate multi-display load, not any single feature. Preview now animates ONLY the main display by default and covers the others with plain black windows (zero GPU work; matches the black art direction). `SEASONS_ALL_DISPLAYS=1` keeps the simultaneous mode as explicit known-dangerous opt-in. Ladder results recorded in docs/CRASH-ANALYSIS.md.

### Added
- Standalone menu-bar app ("Seasons.app", LSUIElement): leaf icon in the menu bar with Start Now, season override (Auto/fixed/Off), idle-start timeout (never/5/10/15/30 min via CGEventSource idle detection), and Launch at Login (SMAppService). On start it fades the engine in fullscreen — animated on the main display, black covers elsewhere per the crash policy — and dismisses on any input. This replaces the .saver as the daily-driver delivery; the system screensaver stays disarmed.
- Phase F multi-species seasons: a season can now declare a `species[]` array — each entry gets its own sprite set, weight share of the particle buffer (contiguous ranges, one instanced draw per species via baseInstance), motion model, sizes, mesh curvature, material, and hue jitter, all inheriting season defaults. New MODEL_SAMARA helicopter motion (fast fixed-sign autorotation, tight helix, papery translucent-wing material). Autumn is now maple (40%) + oak (30%) + birch (18%) + samara (12%). Mesh curvature recipes re-keyed by motion model with per-species curl{} overrides.
- Phase E materials: surface maps (tangent normal / thinness / AO) baked from each sprite's albedo by a compute kernel at load time — no asset pipeline. meshFS gains vein-level normal perturbation (detail responds to key and rim light as particles tumble), per-species subsurface transmission (petal rims glow pink, leaf margins amber, crystal arms cool blue when backlit), AO-shaded ambient, and hash-gated facet glints for snow that wink as crystals wobble and bloom through the pyramid. New material{} JSON block with per-model defaults.
- Winter snow regenerated: 8 crystalline variants (dendrite/plate/needle mix, vibrant icy blue-white with prismatic edge detail) replace the original 4 muted flakes; raw fal.ai sources for the full new family (maple, oak, birch, samara, blossom, hero crystal) staged under tools/raw/ for the multi-species phase.
- Per-instance OKLCH hue jitter (`hueJitterDeg` per season): each sprite instance gets a stable seed-derived hue rotation, chroma scale, and lightness scale applied in OKLab space at sample time — autumn ±14° spreads one maple set across crimson/orange/amber/gold, spring ±6°, winter ±3°. Roughly triples perceived variety at zero asset cost.
- Phase D choreography: cinematic depth distribution (`depthBias` pow-curve — many small far, few large near; size coupled to depth), calm-baseline density with gust release (a fraction of particles park offscreen in calm air and shake loose when a traveling front's local wind passes over them — gusts visibly thicken the fall, then the field thins back), and deterministic hero events (every 25–50s one oversized near-field leaf/petal performs a flutter→autorotation→glide showcase crossing; schedule staggered per display via the world seed so screens never fire together). New `choreo{}` JSON block; fireflies/generic never park; counts raised (autumn/spring 240, winter 460) for reserve head-room.
- Phase C species aerodynamics: per-species motion models where orientation derives from the same state that drives translation. Leaves run a Tachikawa falling-card state machine — FLUTTER (rocking seesaw whose sideslip peaks a quarter-phase ahead of the rock, flat-stall slowing the descent, the rock itself being the mesh orientation) / TUMBLE (gust-triggered constant-sign autorotation with Magnus glide and lift) / GLIDE (settling out). Petals descend in breathing helical gyration with a cupped seesaw in gyre phase. Snow strata: terminal velocity tied to flake size at spawn, micro-turbulence inversely scaled (small flakes dance, big flakes sail), slow plane-wobble. Fireflies steer — Ornstein–Uhlenbeck wander plus weak attraction to three slowly roaming per-display attractors (visible congregations), CRUISE/PERCH/DART states, and species-accurate flash trains (~0.45s sin² flash, 3.5–6.5s dark, ~1 in 8 double-flashers) replacing the sine pulse. Rain streaks tilt by each drop's LOCAL wind so passing gusts visibly rake the rain. New `motionModel` + optional `aero{}` JSON per season; `generic` fallback preserves legacy physics for custom styles.

- Phase B wind world: divergence-free curl-noise turbulence field plus traveling gust fronts (4 staggered deterministic lanes, epoch-hashed direction/speed/strength), evaluated at `worldPos = pos + worldOrigin` as a pure function of the shared clock — all displays render ONE continuous wind field with zero IPC, and a gust visibly sweeps monitor to monitor. Wind coupling is per-particle drag relaxation (`relaxTau` — light things catch the air faster), replacing the metronomic sine sway entirely. Windward-edge respawn bias keeps sustained side-wind from emptying one side. `worldSeed` (hashed display origin) folds into particle seeds so screens never render synchronized clones. New `wind{}` JSON block (windMax-derived defaults), `WindModel` unit tests, shot-harness sequence mode (`[seqEvery]`) + `SEASONS_TIME_OFFSET` + `SEASONS_WORLD_ORIGIN` for cross-display QA.
- Per-season `light{}` and `grade{}` JSON blocks: every lighting and grade parameter (key/ambient/rim light, exposure, saturation, vignette, grain, CA, filmic white, split-tone tints, bloom mix) is now tunable per season via optional JSON, with engine defaults for absent fields. Colors in OKLCH, decoded to linear P3.
- Phase A grade & honesty pass: distance now dims luminance instead of alpha (sprites occlude solidly instead of ghosting; `spriteOpacity` 1.0 for image seasons), grain and vignette are luminance-gated so the void renders true (0,0,0) — verified by pixel sampling, Hable filmic tonemap with white-point normalization replaces bare exposure, shadow/highlight split-toning, three-scale bloom pyramid (1/2 + 1/4 + 1/8 res: halation + glow + atmosphere), chromatic micro-aberration on the DOF blur, and a second cool top-back rim light separating sprites from the black field. Removed the wind spin-nudge and vertical-lift hacks (superseded by the Phase B wind model).

### Fixed
- Root cause CONFIRMED from the second panic log (`DCPEXT0 PANIC - [CED] CLLT escalation - power(6)`, AppleDCP t605xdcp, macOS 26.5.1): requesting an EDR fullscreen surface on an EXTERNAL display drives its Display Coprocessor into an unsatisfiable power escalation and panics the SoC. Log archived locally, not published.
- Second SoC panic (2026-06-10) reproduced on the SAFEST ladder rung — single display, 60Hz, MetalFX disabled — exonerating MetalFX churn and multi-display as necessary conditions and pointing at the EDR drawable path (`wantsExtendedDynamicRangeContent` + rgba16Float scanout). Presentation is now SDR by default: 10-bit Display P3 drawable (`bgra10_xr_srgb`, no extended-range content) with composite clamped at 1.0; the internal rgba16Float linear pipeline is unchanged. EDR is opt-in via `SEASONS_EDR=1`, marked experimental. A new `present` pass decouples the drawable's pixel format from the internal chain (replaces the same-format blit after MetalFX).
- Crash mitigation for the 2026-05-31 M5 SoC power-rail panic (docs/CRASH-ANALYSIS.md): Governor rewritten with hysteresis — coarse 0.1 steps, dead-band between shed/recover thresholds, sustained-dwell requirement (0.75s shed / 2.5s recover), and a 1.5s post-change cooldown so the render scale can never oscillate and churn MetalFX scaler/HDR-target reallocation. Six unit tests cover sustained trends, momentary spikes, dead-band hold, cooldown rate-limiting, and bounds.
- `SEASONS_DISABLE_METALFX` env switch forces the known-safe baseline (fixed native scale, no scaler ever built); `SEASONS_FORCE_FPS` caps the display-link rate (30–120) to relieve the display power rail.
- Command-buffer completion handler now logs GPU errors (`status`/`error`) via os_log instead of swallowing them.
- Seasons Preview now runs fullscreen on every display (one borderless `.screenSaver`-level window per NSScreen), with `SEASONS_SINGLE_DISPLAY` to isolate the multi-display factor while validating stability.

### Changed
- Background is now pure black for every season: removed the per-season sky-gradient tint and the radial backdrop glow entirely (`atmosphere(for:)` zeroes `skyTop`/`skyBottom`/`glowColor`). The previous near-black field still carried a faint top tint and a soft central glow; both are gone so the sprites and their motion carry the frame. Verified via the headless harness: backdrop corners render `(0,0,0)`, particles intact (lit fraction ~0.09–0.14, peak 255).

### Added
- Rain effect (procedural, no sprites): a new `streak` glyph type renders thin elongated motion-blurred droplet trails aligned to fall + wind, with a bright head / faint tail, depth-faded, premultiplied over the black field. New `rain.json` style (fast vertical fall, light blue-white, gusty) and a cold stormy-night backdrop mood. Non-seasonal styles can be previewed via `SEASONS_FORCE=rain` (loads any seasons/<name>.json directly).
- Regenerated autumn leaf sprites (8 variants) via fal.ai: full fleshy maple leaves with crimson/orange/amber/gold gradients, vein detail, and subsurface translucency — replaces the original thinner 5-leaf set. autumn.json spriteCount 5 → 8.
- Polish pass (black-background art direction): backdrops dropped to near-black per season (frame mean ~0.35 → ~0.05) with only a whisper of season tint at the top; bloom cut hard (intensity 0.95 → 0.28) and firefly glow toned down (EDR headroom 2.0 → 1.15, bloom 0.9 → 0.45) per feedback that the glow was too bright and not adding value. Focus shifts to sprite quality + motion.
- Gusting wind: a time-varying global wind field (layered slow sines + gust envelope, signed) in the sim, applied as a depth-scaled horizontal push with a faint vertical lift and a spin nudge so leaves/petals/snow drift and gust naturally. Per-season `windMax` JSON field (autumn 90, winter 60, spring 45, summer 20; optional, defaults to 0).
- Seed project: kickoff prompt (PROMPT.md) and web-baseline reference (engine, atmosphere CSS, sprite sets) ported from mdpj.me seasonal effect.
- Recover and save original Ideogram v3 sprite-generation prompts, prompt formula, and post-process command from prior build sessions (reference/sprite-prompts.md).
- Design spec for the native Metal screensaver: rendering host, EDR/P3 pipeline, GPU particle sim, bloom/DOF/grain post chain, MetalFX adaptive upscaling + per-display performance governor, data-driven season config, and asset pipeline (docs/superpowers/specs/2026-05-30-seasons-screensaver-design.md).
- Implementation plan: 10 phases, task-by-task with TDD for pure-logic units and build/visual verification for GPU units, from sprite generation through four-season verification and docs (docs/superpowers/plans/2026-05-30-seasons-screensaver.md).
- Native-resolution sprite source art (1024px transparent PNG) generated via fal.ai Ideogram v3: snow (4), petals (6), leaves (5); plus the reusable generation runbook (tools/generate-sprites.md).
- Sprite post-process pipeline (tools/process-sprites.sh, pack-sprites.sh): trim, fit object to 880px inside a rotation-safe 1024 square, straight-alpha RGBA output into Resources/sprites/.
- Metal-backed `.saver` scaffold: ScreenSaverView host with a CAMetalLayer backing layer (RGBA16Float, extended-linear Display P3, EDR enabled), CADisplayLink-driven render loop targeting 120Hz, idempotent start/stop. xcodegen project (project.yml), Info.plist principal class, and install.sh (build + ad-hoc sign + install to ~/Library/Screen Savers).
- Config and color logic (unit-tested): OKLCH→linear-Display-P3 conversion (Color.swift), data-driven Season model decoding OKLCH configs to P3 (Season.swift), season catalog with web-matching month selection and override resolution (SeasonCatalog.swift), and the autumn season config.
- GPU particle engine: shared Swift/Metal structs (ShaderTypes.h), compute seed/step kernels mirroring the web engine physics (fall, sway, rotate, tumble, pulse, edge-fade, respawn), mip-mapped sprite texture-array loader, and instanced sprite render pipeline with real Y-axis tumble and premultiplied blending into an HDR scene target.
- Headless render harness (tools/shot, `seasons-shot`): renders N frames of a season to a PNG offscreen for visual QA without the screensaver host or a GUI. Renderer decoupled from the app bundle (library + sprites injected) so both the saver and the harness drive it.
- Fix: replace the particle simulation's correlated LCG with a PCG-style hash so per-particle random streams decorrelate; eliminates the visible horizontal banding where leaves fell in fixed ranks.
- Fix: load the Metal library from the screensaver's own bundle (`makeDefaultLibrary(bundle:)`) instead of `Bundle.main`. A `.saver` is a loadable bundle hosted by another process, so the default lookup found no metallib. Added an `animateOneFrame` fallback so rendering also runs where `CADisplayLink` is inactive (System Settings preview).
- Fix (blank screensaver root cause): month-based auto-selection chose a season whose config file did not exist yet, and `SeasonCatalog.load` force-unwrapped the missing URL, crashing on the first frame. `load` now returns an optional and never crashes; `displaySeason` falls back to any available config. Hardened bundle resolution (NSObject-rooted marker class) and built the saver universal (arm64 + x86_64) so it loads in either host architecture. Added `os.Logger` lifecycle instrumentation.
- Winter, spring, and summer season configs (counts scaled up for the cinematic-faithful target: snow 700, petals 500, fireflies 400).
- Seasons Preview app target: a standalone fullscreen AppKit app that runs the real SeasonsView/Renderer on the main display (Esc/click to quit). Stop-gap delivery and live dev preview while Tahoe's screensaver host does not load classic `.saver` bundles; shares the engine with the `.saver` target.
- Fix: load sprite textures as sRGB so gamma-encoded art decodes to linear correctly in the HDR pipeline (previously treated as linear and blown out toward white).
- Regenerated petal sprites with richer, clearer cherry-blossom pink (rose blush at base, visible veins, translucent edges) and retuned spring to fewer/larger/more-present particles (count 130, size 30–66, opacity 0.9) for a higher-quality, more colorful look.
- Real 3D particles: each particle is now a curved, tessellated mesh (cupped petal, folded/curled leaf, faceted snow) with computed normals, skinned with the sprite art, tumbling on a random 3D axis. Real-time lighting: warm key + cool ambient + backlit subsurface translucency + soft specular sheen.
- Cinematic post-processing stack ("dawn sakura" lush-dramatic grade): graded atmospheric backdrop (vertical gradient + warm radial glow, per-season mood), HDR bloom (bright-pass + separable gaussian), exposure, saturation grade, and vignette composited to an EDR-safe HDR target. Per-season backdrop/light presets for spring/autumn/winter/summer.
- Mixed white-and-pink petal set (10 single-petal variants: white cherry/dogwood + blush pink cherry) for variety; retuned spring grade dimmer and less pink with a near-white key light per art-direction feedback.
- Depth-of-field: particle pass now writes a coverage-weighted circle-of-confusion (MRT) from per-particle depth; composite blends sharp scene toward a half-res gaussian by CoC so far particles melt to bokeh. Added aerial-perspective fade (far particles fainter), wider size range for big-near/small-far depth composition, and a subtle composite grain.
- Firefly glow render path: procedural additive light orbs (radial EDR falloff, breathing pulse) for the glow glyph type, blooming through the post stack. All four seasons now tuned to the cinematic bar — dawn-sakura spring, golden-hour autumn, moonlit-cool winter, warm-dusk firefly summer.
- Season override hook: `SEASONS_FORCE` env var (and a Seasons Preview arg) selects a fixed season for dev/preview; foundation for the config-panel override.
- Top-level README: build/run (preview app, headless harness, .saver), the tuning-knob map (season JSON, grade/light/atmosphere in Renderer, mesh curl, shader math), and the sprite-regeneration recipe.
- Performance governor (unit-tested): closed-loop controller that nudges the render scale toward a target GPU frame time (EMA-smoothed, fast shed / slow recover, clamped). Resolution scale is the only knob; particle count and post-FX stay fixed.
- MetalFX spatial upscaling driven by the governor: the full graded scene renders at an adaptive internal resolution and is reconstructed to native size (HDR color mode), so multi-display / high-DPI setups hold frame rate without cutting particles or effects. GPU frame time is sampled per command buffer and fed back into the governor; output is always native size (verified: forcing 0.3 internal scale halves measured edge energy). `SEASONS_FORCE_SCALE` env overrides scale for QA.
- Reduce Motion support: when macOS `accessibilityDisplayShouldReduceMotion` is set (or the user picks "Off"), the screensaver renders the static graded backdrop (no simulation, no particles). Verified via the harness (`SEASONS_STATIC`): backdrop brightness preserved, particle edge energy drops ~95×.
- Per-display isolation, preview detection, and idempotent teardown: each screen's view owns its own renderer/display-link/governor. A small frame (or `isPreview`) is treated as the System Settings preview — lighter particle count (35%) and 30Hz — to work around the unreliable Tahoe `isPreview` flag. `startAnimation` is re-entrant-safe; `stopAnimation`/`deinit` release the renderer and timer so a re-instantiated view never leaks a live GPU loop.
- Preferences wrapper (`Prefs`) over ScreenSaverDefaults for season selection and bloom/DOF quality toggles (SeasonSelection storage mapping is unit-tested).
- SwiftUI configuration sheet (`configureSheet`): season override (Auto / Winter / Spring / Summer / Autumn / Off) and Bloom / Depth-of-field toggles, persisted via `Prefs`. The view resolves its season from the preference (env override still wins for dev), renders the still backdrop for "Off", and gates bloom/DOF per the toggles.
- Per-display particle count scaling (`countScale`) so the preview thumbnail runs lighter than the full-screen field.
- Developer docs under `docs/`: engine overview (frame pipeline end to end), season config reference (every JSON field + grade-override note), add-a-season guide, and the sprite-generation recipe.
